# PAYO v3 Implementation Plan (recipients, in-chat PIN, billers, Urdu)

> Subagent-driven: one implementer per phase, review after each, orchestrator commits.
> **Spec (binding):** `docs/2026-09-03-payo-v3-recipients-bills-design.md`.

## Global constraints
Roadmap globals + v2 revamp constraints apply (paisa ints, standard response shape, pending
action → PIN → execute, kit components/tokens only, lucide icons, ≥44pt, i18n parity, tests
green before commit, nothing pushed).

## V1 — Backend (services/backend)
- [ ] V1.1 `Institution` model + seed (~35 per spec §2, `popular` flag) + `GET /institutions?q=`.
- [ ] V1.2 `POST /transfers/resolve` (PAYO real-user lookup; wallet phone normalisation
  `03xx`→`+923xx`; bank IBAN/account validation; deterministic titles via `resolveFakeTitle`).
- [ ] V1.3 `Recipient` model (replaces `Contact`) + `GET/POST/DELETE /recipients` (search,
  409 on duplicate, `lastUsedAt`), remove `/contacts`, `/banks*`, `Bank` model.
- [ ] V1.4 `POST /transfers` new body `{ to: { recipientId } | { institutionId, identifier },
  amountPaisa, note? }`; executor payload carries institution/identifier/title/linkedUserId;
  fee rule (banks 2500, wallets 0); execute response `recipientSuggestion` for send kinds;
  `lastUsedAt` bump when sending to a saved recipient.
- [ ] V1.5 `SavedBiller` model + `GET/POST/DELETE /saved-billers`; billers seed extended (12);
  `bills/due` includes saved billers' due bills; execute response `billerSuggestion`.
- [ ] V1.6 Seed: no recipients/saved billers; Ammi's due bill kept. Roadmap Contract 1 updated.
  Full suite + typecheck green.

## V2 — AI service (services/ai)
- [ ] V2.1 Backend client + tools per spec §3; new card models (`institution_chips`,
  `recipient`, `recipient_chips`, `biller_chips`, `save_prompt`); remove
  `search_contacts`/contact_chips.
- [ ] V2.2 Prompt policy (both languages): identifier w/o institution → ask with chips; never
  send before a resolved recipient card was confirmed; saved-recipient search first when a
  name is given; bills: saved billers first, else ask biller + reference.
- [ ] V2.3 Language policy: `reply_language(input_text, ui_language)` → 'ur' when the text
  contains Arabic-script characters, else ui_language; audio path uses the transcript's script.
  Post-check: `language=='ur'` and reply has no Arabic-script chars → one re-prompt.
- [ ] V2.4 STT: prompt says speech may be Urdu or English; Urdu MUST be written in Perso-Arabic
  (Nastaliq) script, never Devanagari; tests on prompt text + a `has_arabic_script` helper.
- [ ] V2.5 pytest green; scripted-model tests for: number-without-institution → chips; saved
  recipient dup → chips; bill flow; Urdu-script input → Urdu prompt.

## V3 — Mobile: PIN sheet + chat cards (apps/mobile)
- [ ] V3.1 `PinSheet` component (bottom sheet; dots, 72pt keypad, shake, lockout message;
  `executeAction` inside; promise-style API `openPinSheet(action) → transaction`).
- [ ] V3.2 Chat: `ConfirmationCard` opens `PinSheet` (no navigation); on success append
  `success` + `save_prompt` cards (the latter with inline nickname input → POST
  /recipients or /saved-billers); renderers for `recipient`, `recipient_chips`,
  `institution_chips`, `biller_chips`; chips send text turns.
- [ ] V3.3 Replace the PIN stage in `confirm/[actionId]` with `PinSheet`; pockets/requests
  use it too. Remove the old PIN page code.

## V4 — Mobile: classic Send + Bills (apps/mobile)
- [ ] V4.1 Send: identifier screen with saved-recipients list (search/delete) → institution
  picker (search, popular first, initials logo) → resolved recipient → amount → confirm
  details (amount/fee/total/channel) → PinSheet → success (+ save toggle w/ nickname).
- [ ] V4.2 Bills: billers by category + Saved section → consumer no → details → confirm →
  PinSheet → success (+ save toggle). Pay hub: "Saved recipients" tile.
- [ ] V4.3 Remove old contacts/bank screens+endpoints; i18n parity; jest + tsc green.

## V5 — QA + docs

- [ ] V5.2 Suites green; QA-REPORT (v3 section), DEMO-SCRIPT + README updated; commit.
